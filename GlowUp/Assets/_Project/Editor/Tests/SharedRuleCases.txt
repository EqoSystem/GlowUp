# Examples for the rules the app and the admin website must share word for word:
#   the app:      TextKey.cs and ProductIndex.cs (Assets/_Project/Scripts/Data)
#   the website:  _Shared/glowupRules.js
# Both are tested against this one list (SharedRuleCasesTests.cs in Unity, tests/rules.test.mjs on the website),
# so the two can never drift apart. The make-up rule has its own list: MakeupScopeCases.txt.
#
# Each line: the name of the rule | what goes in | what must come out
#   key        | a name                  | its comparable key
#   slug       | a name                  | the key with _ between the words (used inside document ids)
#   compact    | a name                  | the key without spaces
#   same       | name 1 | name 2         | yes or no: do the two names give the same key?
#   squashsame | name 1 | name 2         | yes or no: the same name once camera look-alikes are ignored (rn/m, 0/o, 1/l/i)?
#   barcode    | what was read           | the barcode key (nothing = it cannot be a barcode)
#   brands     | brand 1 | brand 2       | yes or no: do the two names mean the same brand?
#   scanid     | brand | product name    | the id a product gets when the app adds it from a scan
#   brandid    | brand                   | the id a brand gets when the app adds it from a scan
#   stoplist   | a piece of label text   | the stoplist entry it holds (nothing = it holds none)
#   shape      | a piece of label text   | ok or wrong: can it be an ingredient name at all?
#
# \uXXXX stands for one character given by its code: \u00e9 is an e with an acute accent, \u0020 is a space
# (spaces at the ends of a column are cut off, so a space that matters is written as its code).
# Lines that start with # are notes.
