# Architecture (short)

The detailed, code-derived description with diagrams is `docs/ARCHITECTURE_AS_FOUND.md`. In short:

- **Android app** (Unity 2022.3.62f3, C#): 15 scenes generated by Editor builders. Labels and barcodes are read on the phone (Google ML Kit through our
  Java plug-ins); the ingredient list is parsed (`IngredientTextParser`) and compared with the user's Skin Profile on the phone
  (`ProductAnalysisEngine`); AR Try-On uses AR Foundation / ARCore 5.2.2 with a guided fallback. Firestore persistence and our own write queue
  (`SyncQueue`) make it work offline. When the app cannot name a product it asks Gemini directly (the key is inside the app) or, for a photo snapshot,
  through `api/scan-snapshot.js`. The profile is never sent to an AI.
- **Admin website** (static HTML + ES modules on Vercel): Dashboard, Brand & Product Inventory, Ingredient Curator, Recycle Bin. Shared rules with the app in
  `_Shared/glowupRules.js` (make-up scope, source kinds, evidence tiers). File imports are read in the browser; only documents that are not in a known
  layout go to the AI (`api/assist-ingredient.js`: Gemini, then Groq, then Mistral; keys are Vercel environment variables).
- **Firebase**: Authentication (e-mail/password, Google, Facebook) and one Cloud Firestore database. `firestore.rules` is the only gatekeeper: everybody reads
  the catalogue, admins write it, the app may only add Pending entries and count scans, and each user alone reads and writes their own profile and scans.
  Storage is not used (`storage.rules` closes it).

Data rules: `GlowUp-Admin_AI_Testing/FIRESTORE_SCHEMA.md`, `docs/DATA_MODEL.md`, `docs/DATA_SOURCE_POLICY.md`.
