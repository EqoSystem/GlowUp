Part F · Data25. Database type and management

In plain words. GlowUp uses Cloud Firestore, a NoSQL document database: data is stored as documents (like small JSON records) inside named collections, not as tables with joins. One project serves both the app and the website. The phone keeps its own copy and works offline; the website keeps a copy in the browser. {V:Scripts/Data/FirebaseBootstrap.cs, Scripts/Data/OfflineCache.cs, GlowUp-Admin_AI_Testing/_Shared/adminStore.js}

Why Firestore fits (no written reason in the repository): the team already used Firebase Auth; Firestore has a Unity SDK with offline persistence and a JavaScript SDK for a static website; security rules replace a custom backend; the free tier needs no server. The decision to stay on Firestore instead of moving to Supabase is the team's own and is not recorded in the repository. {I:Scripts/Data/FirebaseBootstrap.cs, _Database/firebase-console.js, FIRESTORE_SCHEMA.md "keeps the free tier safe"} {N:a written comparison Firestore vs Supabase / SQL in the repository}

25.2 Document shapes and relationships

  • Brand → product: products.brandId holds the brand's document id, plus a copy of brandName (renaming a brand updates the copies). {V:FIRESTORE_SCHEMA.md products}
  • Product → ingredient: by name (ingredients[], as printed) and, as a light summary, by id (ingredientIds[]); per-product notes in ingredientNotes. No safety verdict is stored on a product. {V:FIRESTORE_SCHEMA.md "How the data is split"}
  • Ingredient → lists: ids of config/lists items in allergenTags, avoidForConditions, highlights ... Ids never change; labels can. {V:FIRESTORE_SCHEMA.md config/lists}
  • Types: text, number, yes/no, list, map, server timestamp; app-written times are Unix seconds (addedAtUnix, scannedAtUnix). {V:FIRESTORE_SCHEMA.md field tables}

25.3 Indexes, queries, caching, consistency

  • Indexes: no firestore.indexes.json; only single-field queries are used, which Firestore indexes automatically. {V:GlowUp-Admin_AI_Testing/firebase.json} {N:firestore.indexes.json (composite indexes)}
  • App queries: changed entries by updatedAt / createdAt / addedAtUnix greater than the newest stamp seen; products by brandName in pages. {V:Scripts/Data/CatalogSync.cs lines 93-95, Scripts/Data/ProductRepository.cs lines 220-258}
  • App caching: first run downloads everything (about 700 documents); then only changes, a count check to detect deletions, a full download once a day, nothing within 10 minutes of the last check. {V:Scripts/Data/CatalogSync.cs header, Scripts/Scan/ScanRules.cs lines 34-36}
  • Look-ups on the phone: ProductIndex tables by barcode, brand + name, alias, word — no database read per scan for known products. {V:Scripts/Data/ProductIndex.cs header}
  • Website caching: lists kept in memory and localStorage, wiped on sign-out; changes only. {V:_Shared/adminStore.js header}
  • Offline writes: SyncQueue replays queued writes; a write refused for good is dropped so it cannot block others. {V:Scripts/Data/SyncQueue.cs header}
  • Consistency: verdicts computed when read (no stale copies); binning sets status Inactive in the same write; config/lists refuses to overwrite a newer version. {V:FIRESTORE_SCHEMA.md}
  • Read counting: ReadCounter logs reads per call, scan and session in development builds. {V:Scripts/Data/ReadCounter.cs}

Part F · Data28. Ingredient information, references and flags

  • How descriptions link to sources: each ingredient has sources ("page title | https://address"); the kind of page is worked out when shown (regulator, medical, maker, reference, public, retailer, other) by the same rule in app, site and server, tested against shared cases. Assist with AI keeps only regulator, medical and reference pages for an ingredient's description. The Curator auto-approves a draft only on a known dermatology/pharmacy/regulator link, and only warnings. {V:FIRESTORE_SCHEMA.md, Scripts/Scan/ListSources.cs, _Shared/glowupRules.js, api/assist-ingredient.js, commits f4da39b, 62c3be0}
  • Flags: riskLevel harmful = prohibited/restricted by a regulator; caution = documented concern (allergen/irritant); umbrella terms (e.g. Fragrance) warn that hidden substances are possible; allergen families; condition and skin-type flags; minimum age. {V:IMPORT_FORMAT.md, FIRESTORE_SCHEMA.md ingredients}
