Part G · Security32. Database security in practice

  • Roles: three in practice: public reader, signed-in app user, admin (by admins document). No custom claims. {V:firestore.rules} {N:Firebase custom claims}
  • Least privilege: the app's writes are narrow (create-only, fixed keys, Pending); admins cannot read personal data; the AI function uses the caller's own token instead of a service account. {V:firestore.rules, api/scan-snapshot.js header}
  • Admin-only collections: scanActivity, suggestions, productIngredientSuggestions, pending_product_images are readable only through isAdmin(). {V:firestore.rules}
  • Backups / exports: tools/downloadCatalogue.mjs saves the three public collections; the Recycle Bin downloads a JSON copy before deleting forever. Personal data is not backed up by these tools. No scheduled Firestore export is configured. {V:tools/downloadCatalogue.mjs header, _Admin_Recycle_Bin/adminRecycleBin.js header} {N:scheduled Firestore backups / point-in-time recovery}
  • Environments: one Firebase project for development, testing and the demo; the app's tests run on pure logic, not on the live database. {V:.firebaserc} {N:separate test / staging Firebase project}
  • Shared admin login: one admin account is shared by several people, so changes cannot be traced to a person. {V:_Shared/adminLayouts.js header}
